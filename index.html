How Redacta works

One boundary, enforced in code — not in a policy PDF.

1

Prepare the on-device model

On a user action, Redacta calls initializeDeviceModel() so Chrome downloads or confirms Gemini Nano. Download progress is a first-class state in the interface, never hidden.

2

Scan stays on the device

The document is sent to a model created with ONLY_ON_DEVICE and a JSON schema constraint. It returns structured entities — names, IDs, accounts, addresses, amounts, dates — plus a sensitivity score and a local summary. This step produces zero network traffic.

3

You approve the redaction

Every span is highlighted in place and listed with its type, confidence and sensitivity. Critical and high spans are redacted by default; you can keep or redact any span individually. The redacted document is shown verbatim before anything else happens.

4

Cloud sees redacted text only

The analysis model is constructed from the redacted artefact. Its function signature accepts that artefact and nothing else, so raw personal data has no code path to the cloud. Each response reports its own inferenceSource, which the privacy ledger records next to the payload length and fingerprint.

Scope and honesty notes

Redacta is a redaction assistant, not a legal guarantee: a human reviews every span before a document is shared, and unusual documents can contain data types outside the extraction schema. On-device inference requires Chrome on desktop with Gemini Nano available; on any other browser the scan lane refuses rather than degrading to a cloud upload. This prototype build runs its inference in clearly labelled simulation mode until a Firebase project is configured; the production module (js/hybrid.js) implements the same flow against the real Firebase AI Logic SDK.
